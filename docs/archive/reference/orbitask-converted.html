The cell

It is not a number to pick — it is a sum

You are right that the drawing and the grid disagree, and the reason is that the cell was chosen and the controls were chosen separately. A control is 42px. A widget pads it by 12 on each side. So a widget one cell tall has to hold 42 + 12 + 12 = 66px — and anything the cell has above that is slack the widget cannot use.

The grid is elastic — the cell is the board's width divided by however many columns fit a target — so the question is not what is the cell but what target keeps it near 66 at every width. Measured by sweeping every board width from 360 to 1300px:

Target, narrow → wideCell rangeWorst distance from 66Average
84 → 68 (today)65–93px27px8.7px
72 → 6260–81px15px3.5px
70 → 64 ← recommended61–79px13px2.8px
66 → 66 (fixed)59–73px7px2.2px

Recommendation: 70 → 64. The fixed target tracks 66 most closely, but it also removes the one thing the elastic target is for — a phone gets a bigger cell so a tap target stays a tap target. 70 → 64 keeps that and cuts the average error from 8.7px to 2.8px, which is the difference between a widget that fits its cell and one that floats in it.

And it is a sum, not a preference: change the control height or the widget padding and the target moves with them. That is the only version of this that cannot drift again.
